# 8. Run the same code as 32- and 64-bit

**Goal:** see how the emulator runs both RISC-V widths, how it *chooses* which,
and how the same C source compiles differently for each.

**You will use:** the ELF-class auto-detection - you never pass a width flag;
the emulator reads it from the ELF header and selects the RV32 or RV64 core.

The example is `primes-fast.c` again, built once for each width.

---

## Step 1 - build the same source both ways

The RV32 build is already there (`make out/elf/primes-fast.elf`). Build an RV64
one with the 64-bit startup, log and linker script:

```bash
cd tutorials
riscv32-unknown-elf-gcc -march=rv64imac -mabi=lp64 -mcmodel=medany \
    -nostdlib -nostartfiles -fno-builtin -O2 -g -I../programs \
    -T ../programs/hello64.ld -o /tmp/primes-fast-rv64.elf \
    ../programs/crt0-64.S ../programs/uart.c ../programs/log64.c primes-fast.c
```

(Note `lp64`, `crt0-64.S`, `log64.c` - the 64-bit variants. See
[../doc/WRITING-PROGRAMS.md](../doc/WRITING-PROGRAMS.md) section 6.)

## Step 2 - run both, no width flag

```bash
../bin/riscv_emulator --machine qemu-virt --log-dir /tmp out/elf/primes-fast.elf | head -1
../bin/riscv_emulator --machine qemu-virt --log-dir /tmp /tmp/primes-fast-rv64.elf | head -1
```

```
Loading ELF file:   out/elf/primes-fast.elf
Loading ELF64 file: /tmp/primes-fast-rv64.elf
```

The emulator says **ELF file** vs **ELF64 file**: it read the ELF class byte
and picked the 32- or 64-bit core automatically. Both print the same answer
(`primes below 4000: 550`) - the algorithm is width-independent.

## Step 3 - see the difference in the code

Same C, different instructions. Disassemble `count_primes` in each:

```bash
riscv32-unknown-elf-objdump -d out/elf/primes-fast.elf | sed -n '/<count_primes/,/ret/p'
riscv32-unknown-elf-objdump -d /tmp/primes-fast-rv64.elf | sed -n '/<count_primes/,/ret/p'
```

RV32:
```
addi   s0,s0,1          # n++
add    s1,s1,a0         # count += is_prime(n)
```

RV64:
```
addiw  s0,s0,1          # n++   (32-bit add, sign-extended into a 64-bit reg)
addw   s1,s1,a0         # count += ...
```

On RV64 the compiler uses the **W-suffix** forms (`addiw`, `addw`) for 32-bit
`uint32_t` arithmetic: they compute a 32-bit result and sign-extend it through
the full 64-bit register, which is how RV64 keeps 32-bit types behaving
correctly in 64-bit registers. Same source, genuinely different machine code,
each running on its own core in the same emulator binary.

## What to take away

* One emulator binary runs both RV32 and RV64; the **ELF class** selects the
  core, so you never pass a width flag - just hand it the binary.
* The load message (`ELF file` vs `ELF64 file`) confirms which core ran.
* The same C yields different instructions per width (`add` vs `addw`); the
  64-bit core also has the full RV64 register width, `LD`/`SD`, and the Sv39 MMU.
